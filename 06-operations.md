# 06. Эксплуатация: что делать, когда всё уже работает

Цель шага: сервер и три агента живут месяцами без сюрпризов. Файл читается целиком до начала установки, а разделы применяются по мере появления потребности. Пометки блоков команд те же: `# администратор`, `# агентский пользователь`, `# человек`.

Предыдущие шаги: [01-server.md](01-server.md), [02-agents.md](02-agents.md), [03-telegram-hub.md](03-telegram-hub.md), [04-approaches.md](04-approaches.md), [05-fleet-patterns.md](05-fleet-patterns.md).

## 1. Контракт установки для AI-агента

Тот же короткий блок стоит в начале [README.md](README.md). Если установку ведёт AI-агент:

1. Сначала прочитать все документы набора, потом выполнять команды.
2. Заполнить таблицу: пользователи Linux, адрес сервера, алиасы чатов, выбранные движки расшифровки. Значения в `<...>` не угадывать: нет значения, значит вопрос владельцу.
3. Систему не переустанавливать. Переустановка только по прямому решению владельца для конкретного сервера.
4. Отказ системы и запрос разрешения не обходить другим пользователем, другим инструментом или другой записью команды: сообщить владельцу.
5. На блоках "человек" (пароли, BotFather, вход через браузер, коды из SMS) остановиться и ждать.
6. Секреты не писать в переписку, не печатать, существующие файлы секретов не заменять.

## 2. Расходы и лимиты

- Три процесса агентов не дают трёх независимых лимитов: если они работают под одной подпиской, лимит общий. Расход смотрит человек в кабинете подписки, агент своего остатка не видит.
- В кабинете подписки включить уведомления о расходе. Автоматическое платное продолжение после исчерпания лимита не включать без решения владельца.
- Фоновые задачи (циклы, цели, длинные ревью) получают потолок по ходам или времени (раздел 5 в [04-approaches.md](04-approaches.md)).
- Облачная расшифровка голосовых (если выбрана) оплачивается отдельно по API-тарифу провайдера, а не подпиской. Локальный движок `cpu` платы не имеет.
- Лимит исчерпан: агент перестаёт брать новые задачи, заканчивает начатое и докладывает; брошенная на нуле работа при возобновлении читается с нуля.

## 3. "Агент молчит": диагностика и аварийная остановка

Молчание имеет пять причин. Проверять по порядку, сверху вниз.

| # | Причина | Проверка | Что делать |
|---|---|---|---|
| 1 | Хаб не работает | `systemctl --user is-active tg-hub.service`, `tail -5 ~/tg-assistant/var/errors.log`, время изменения файлов в `var/logs/` | Перезапустить службу (шаг 4 из 03) |
| 2 | Наблюдатель завершился | В окне агента нет запущенного `tg-watch.sh`, нет уведомления о Monitor | Попросить агента запустить наблюдатель заново (у Monitor есть срок) |
| 3 | Процесс агента завершился | `tmux ls`, в окне голая оболочка | Запустить `claude` в существующей сессии |
| 4 | Агент ждёт разрешения | `tmux capture-pane -p -t personal \| tail -20` показывает вопрос о разрешении | Ответить человеком, при повторах расширить `settings.json` узким правилом |
| 5 | Исчерпан лимит подписки | Сообщение о лимите в окне агента, расход в кабинете | Ждать сброса или решение владельца о тарифе (раздел 2) |

Сквозная проверка: написать в группу "ответь одним словом: ок", ответ приходит за 5-10 секунд. Внешний сигнал о недоступности (`healthcheck.sh` из шага 5) идёт через тот же хаб и молчит вместе с ним: для случая "лёг сам хаб" добавить независимое оповещение (почта или внешний сервис проверки доступности).

```bash
# администратор: аварийная остановка отправки без удаления данных
uid=$(id -u agent-personal)
sudo -u agent-personal -H env XDG_RUNTIME_DIR="/run/user/$uid" \
  DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/$uid/bus" \
  systemctl --user stop tg-hub.service
sudo -u agent-personal -H tmux send-keys -t personal C-c
```

Остановленный хаб ничего не отправляет, очередь `var/outbox/` и журналы остаются на месте. Запуск обратно: `systemctl --user start tg-hub.service`.

## 4. Диск и журналы

- Раз в неделю проверять `df -h`, `df -i` (занятость и число файлов) и `free -h`.
- Журналы хаба растут без ограничения. Ротация (администратор), по блоку на каждого агентского пользователя:

```
/home/agent-personal/tg-assistant/var/logs/*.log {
    su agent-personal agent-personal
    weekly
    rotate 8
    compress
    missingok
    notifempty
    copytruncate
}
```

- `copytruncate` обязателен: хаб продолжает писать в тот же файл, а `tail -f` без него остаётся на старом. Наблюдатель `tg-watch.sh` читает укоротившийся журнал с начала. Проверить переход один раз: `sudo logrotate -f <файл>` и сообщение в чат.
- Вложения и кадры видео: `find /home/agent-*/tg-assistant/var/media -type f -mtime +30 -delete`. Исполненные задания очереди: `find /home/agent-*/tg-assistant/var/outbox -name '*.sent_*' -mtime +14 -delete`. Обе команды ставятся в `crontab` пользователя root раз в сутки. Файлы `.failed` не удаляются, пока не разобраны.
- Истории CLI (`~/.claude/`, `~/.codex/`) тоже растут: смотреть их размер при проверке `df -h`.

## 5. Обновление с откатом

1. Записать версии до обновления: `claude --version`, `codex --version`, `uv --version`, `git -C ~/tg-assistant rev-parse HEAD`, в файл `~/work/versions.log` агентского пользователя.
2. Скопировать `chats.yaml`, файл службы и `~/.tg-session/` (права 700) рядом с датой.
3. Обновлять **одного агента** (не боевого), остальных не трогать.
4. Остановить службу, обновить, запустить: `git -C ~/tg-assistant pull --ff-only`, `uv sync`, затем `systemctl --user start tg-hub.service`. Правка окружения работающего сервиса без остановки не выполняется.
5. Проверить текст ("ответь: ок") и голос (короткое голосовое, расшифровка видна в журнале).
6. Откат: `git -C ~/tg-assistant checkout <записанный хеш>`, `uv sync`, запуск службы, возврат `chats.yaml` из копии.
7. Остальных агентов обновлять после успешной проверки.

## 6. Резервные копии и проверка восстановления

- Git-копия настроек ([04-approaches.md](04-approaches.md), раздел 8) не содержит рабочих документов, заметок (`~/work/notes/`) и состояния обработки (`~/.local/state/agent/`). Для них нужна отдельная копия.
- Копия данных шифруется и хранится вне сервера (внешнее хранилище, второй носитель). Снимок диска провайдера единственной копией не считается.
- Файлы сессий Telegram (`*.session`) в копию не кладутся: при потере выполняется новый вход. Если копия нужна, она хранится только зашифрованной.
- Проверка восстановления не реже раза в квартал: клонировать репозиторий настроек и распаковать копию данных в пустую папку тестового пользователя, убедиться, что файлы открываются, а `chats.yaml` и навыки на месте. Копия, которую ни разу не восстанавливали, копией не считается.

## 7. Если сервер скомпрометирован

Порядок действий с доверенного устройства (человек):

1. Не стирать сервер сразу: сохранить для разбора журналы (`journalctl`, `last`, `~/tg-assistant/var/`) на ноутбук.
2. Отозвать Telegram-сессии: Настройки, Устройства, завершить сессию сервера (для userbot это главное).
3. Отозвать токены ботов (`/revoke` в @BotFather), ключи API и OAuth-доступы у провайдеров, GitHub deploy keys в настройках репозиториев, сессии Claude и Codex в аккаунтах.
4. Ограничить доступ к серверу (остановить VPS в панели Contabo).
5. Новый сервер подготовить по этому набору заново. Новые секреты вводятся только на нём. Старые скрипты и конфигурацию не восстанавливать вслепую: сначала сравнить с копией из git по `git diff`.

## 8. Доступ из РФ

- До начала работы проверить с реальных сетей владельцев (домашняя сеть, мобильный интернет): SSH на сервер, панель Contabo (new.contabo.com), страницы входа в Claude и ChatGPT в браузере, Telegram.
- Сервер в Европе, и недоступность из одной сети не означает поломки сервера: проверить из другой сети (например, с телефона через мобильный интернет). Contabo отдельно описывает блокировки маршрутов из РФ (справка "I can't connect to my server, what do I do?" на help.contabo.com).
- Межсетевой экран (`ufw`) при этом не отключается: он не причина блокировки маршрута, а отключённый экран открывает сервер всем.
- Исходящие соединения сервера к Telegram, Claude и OpenAI проверяются с самого сервера: `curl -sI https://api.telegram.org | head -1`.
- Средства обхода блокировок на ноутбуке и телефоне выбирает и настраивает владелец, набор их не описывает.
