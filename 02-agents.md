# 02. Агенты: Claude Code и Codex, отдельный пользователь на каждого

Цель шага: на сервере работают три агента (личный, компании, чатов), каждый под своим Unix-пользователем, в своей сессии tmux, со своими секретами. Сбой или ошибка одного агента не задевает файлы другого.

Предыдущий шаг: [01-server.md](01-server.md) (выполнен, вход по ключу работает).

Термины:

- **Агент**: программа с языковой моделью, которая сама читает файлы, запускает команды и пишет код по поручению. Здесь это **Claude Code** (CLI от Anthropic) и **Codex** (CLI от OpenAI).
- **CLI** (command line interface): программа, которая запускается командой в терминале, без окон.
- **Unix-пользователь**: отдельная учётная запись на сервере со своей домашней папкой. Один пользователь не может читать файлы другого (если права выставлены правильно) и не может администрировать систему без `sudo`.
- **tmux**: программа, которая держит терминальную сессию на сервере живой после закрытия SSH-соединения. К сессии можно вернуться позже и увидеть всё, что произошло.
- **Node.js**: среда запуска JavaScript. Нужна части инструментов (в том числе установке Codex через npm). **LTS** (long term support): версия с долгой поддержкой, предназначенная для постоянной работы. **npm**: менеджер пакетов Node.js.

## Раскладка пользователей

| Unix-пользователь | Назначение | Права |
|---|---|---|
| `<имя>` (из шага 01) | Владелец, администратор. Агентов под ним не запускают. | sudo |
| `agent-personal` | Личный агент: диалог с владельцем в Telegram с телефона. | без sudo |
| `agent-company` | Агент компании: документы и задачи компании. | без sudo |
| `agent-chats` | Агент чатов: читает рабочие чаты и готовит сводки и черновики ответов. | без sudo |

Правило: **у агента нет sudo и нет доступа к домашней папке другого пользователя.** Агент работает только в своей папке, и ошибка (или вредный текст из чата, см. [04-approaches.md](04-approaches.md)) не выходит за её пределы.

## Шаг 1. Базовые пакеты

Под пользователем `<имя>`:

```bash
sudo apt update
sudo apt install -y tmux git curl build-essential
```

Проверка: `tmux -V && git --version` печатает версии обеих программ.

Память: Claude Code по документации требует не менее 4 ГБ оперативной памяти. Проверка: `free -h` (строка `Mem`, колонка `total`). Три агента одновременно требуют заметно больше: если памяти мало, одновременно запускаются не все.

## Шаг 2. Три пользователя для агентов

```bash
for u in agent-personal agent-company agent-chats; do
  sudo adduser --disabled-password --gecos "" "$u"
  sudo chmod 700 "/home/$u"
  sudo loginctl enable-linger "$u"
done
```

- `--disabled-password`: войти этим пользователем напрямую (по SSH или паролем) нельзя. Владелец заходит в него командой `sudo -iu <пользователь>`.
- `chmod 700`: домашняя папка закрыта для всех, кроме хозяина.
- `enable-linger`: пользовательские службы systemd (нужны в [03-telegram-hub.md](03-telegram-hub.md)) продолжают работать, когда никто не вошёл в систему.

Проверка изоляции:

```bash
sudo -iu agent-company ls /home/agent-personal
sudo -iu agent-company sudo -n true
```

Первая команда печатает `Permission denied`. Вторая печатает отказ (`a password is required` или `is not in the sudoers file`). Если любая из них проходит успешно, изоляции нет, дальше не идти.

Вход в нужного пользователя:

```bash
sudo -iu agent-personal
```

Приглашение меняется на `agent-personal@...`. Выход: `exit`. Все команды шагов 3 и далее выполняются **внутри такого входа, отдельно для каждого агента**, если не сказано иное.

## Шаг 3. Node.js LTS (внутри каждого агентского пользователя)

Node ставится менеджером версий **nvm** отдельно каждому пользователю: без `sudo`, без общих глобальных пакетов, и обновление у одного не ломает остальных.

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.41.0/install.sh | bash
export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"
nvm install --lts
```

Версия скрипта nvm (`v0.41.0`) взята со страницы <https://github.com/nvm-sh/nvm> на момент составления комплекта. Перед выполнением открыть страницу и взять актуальный тег, если он новее.

Проверка:

```bash
node --version && npm --version
```

Обе команды печатают версию. Номер Node соответствует строке "LTS" на <https://nodejs.org/en/download>.

## Шаг 4. Claude Code

Внутри каждого агентского пользователя:

```bash
curl -fsSL https://claude.ai/install.sh | bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
. ~/.bashrc
```

Это официальная установка (native installer) из документации Anthropic. Бинарный файл попадает в `~/.local/bin/claude` и сам обновляется в фоне. Установка через npm (`npm install -g @anthropic-ai/claude-code@latest`, без `sudo`) допустима, но не требуется.

Проверка:

```bash
claude --version
claude doctor
```

Первая команда печатает номер версии, вторая печатает диагностику без ошибок.

**Вход (авторизация).** Нужен платный план: Claude Pro, Max, Team, Enterprise или аккаунт Console (бесплатный план claude.ai Claude Code не включает).

```bash
claude
```

Сервер не имеет браузера. Claude Code печатает ссылку для входа: скопировать её и открыть в браузере на ноутбуке или телефоне, войти в аккаунт, подтвердить доступ. Если браузер показывает код вместо перехода назад, вставить код в терминал в строке `Paste code here if prompted`. Успех: `Login successful`.

Для работы без участия человека (например, при перезапуске) документация предлагает долгоживущий токен: команда `claude setup-token` печатает токен на один год. Он кладётся в файл секретов агента как `CLAUDE_CODE_OAUTH_TOKEN` (см. шаг 7), никуда больше не копируется. Для обычной работы достаточно входа по ссылке.

Проверка входа: внутри `claude` команда `/status` показывает способ входа и аккаунт. Учётные данные на Linux лежат в `~/.claude/.credentials.json` с правами 600 (читает только хозяин).

Источники: <https://code.claude.com/docs/en/setup>, <https://code.claude.com/docs/en/authentication>.

## Шаг 5. Codex

Внутри каждого агентского пользователя, которому нужен Codex:

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

Это официальная установка из README проекта <https://github.com/openai/codex>. Альтернатива через npm (при установленном Node из шага 3, без `sudo`): `npm install -g @openai/codex`.

Проверка:

```bash
codex --version
```

Если команда не найдена, открыть новую сессию (`exit`, затем снова `sudo -iu <пользователь>`): установщик мог добавить путь в профиль оболочки.

**Вход.** Платный план ChatGPT (Plus, Pro, Business, Edu, Enterprise) или ключ API. На сервере без браузера порядок такой.

Основной способ (код устройства):

1. В настройках безопасности ChatGPT включить вход по коду устройства (device code login). Без этого шаг 2 не сработает.
2. На сервере: `codex login --device-auth`.
3. Открыть выведенную ссылку в браузере, войти, ввести одноразовый код.

Запасной способ (перенаправление порта по SSH): с ноутбука открыть `ssh -L 1455:localhost:1455 <имя>@<IP-адрес сервера>`, внутри этой сессии `sudo -iu <агентский пользователь>`, затем `codex login`, и открыть выведенный адрес в браузере на ноутбуке.

Не рекомендуется: копировать `~/.codex/auth.json` с ноутбука на сервер. Файл содержит токены доступа и приравнивается к паролю.

После входа:

```bash
chmod 700 ~/.codex
chmod 600 ~/.codex/auth.json
```

Источники: <https://github.com/openai/codex>, <https://learn.chatgpt.com/docs/auth> (документация по входу, адрес <https://developers.openai.com/codex/auth> перенаправляет туда).

## Шаг 6. tmux: агент живёт после отключения

Внутри агентского пользователя:

```bash
mkdir -p ~/work
tmux new -s personal -c ~/work
```

(Имя сессии: `personal`, `company` или `chats`, по агенту.) В открывшемся окне запустить `claude` или `codex`.

| Действие | Клавиши или команда |
|---|---|
| Отключиться, агент продолжает работать | Ctrl+B, затем D |
| Список сессий | `tmux ls` |
| Вернуться в сессию | `tmux attach -t personal` |
| Закрыть сессию насовсем | внутри неё `exit` |

Проверка: закрыть окно терминала целиком (не `exit`), войти на сервер заново, `sudo -iu agent-personal tmux ls` показывает сессию `personal`.

Ограничение: после перезагрузки сервера сессии tmux исчезают. Перезагрузки редкие и ручные (шаг 8 из [01-server.md](01-server.md)), после каждой агенты запускаются заново: `tmux new -d -s personal -c ~/work 'claude'`.

## Шаг 7. Секреты: файл `.env` с правами 600, не в git

**Секрет** здесь: токен Telegram-бота, ключ API, токен входа. Правила:

1. Секреты лежат в одном файле в домашней папке агента, **вне** любой папки под git:

   ```bash
   install -m 600 /dev/null ~/.agent.env
   nano ~/.agent.env
   ```

   Формат: строки `ИМЯ=значение`, без пробелов вокруг `=`, без кавычек, если в значении нет пробелов.

2. Проверка прав:

   ```bash
   stat -c '%a %U' ~/.agent.env
   ```

   Ожидается `600 agent-personal` (или имя того пользователя, в котором выполняется команда).

3. Если рядом есть папка с git (конфигурация агента, см. [04-approaches.md](04-approaches.md)), в её `.gitignore` записываются маски, и это проверяется:

   ```bash
   printf '%s\n' '.env' '*.env' '*.session' '.credentials.json' 'auth.json' >> .gitignore
   git check-ignore -v .env auth.json
   ```

   Команда печатает строки с совпавшим правилом для каждого имени. Пустой вывод означает, что файл попадёт в коммит.

4. Секрет не вставляется в чат (в том числе в Telegram), в тикет, в письмо и в командную строку (`команда --token=...` остаётся в истории оболочки). Передавать между устройствами: через менеджер паролей.

5. Утёкший секрет считается скомпрометированным: токен бота отзывается в @BotFather (`/revoke`), ключ API пересоздаётся в кабинете провайдера. Удаление из git-истории утечку не отменяет.

Загрузка в окружение перед запуском программы:

```bash
set -a; . ~/.agent.env; set +a
```

## Итоговая проверка шага

Для каждого из трёх агентов:

| Проверка | Ожидание |
|---|---|
| `sudo -iu agent-X ls /home/agent-Y` | `Permission denied` |
| `sudo -iu agent-X sudo -n true` | отказ |
| `sudo -iu agent-X claude --version` | версия |
| `sudo -iu agent-X tmux ls` | своя сессия |
| `sudo -iu agent-X stat -c '%a' .agent.env` | `600` |
